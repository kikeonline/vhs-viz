- `./build.sh --debug` builds a local signed app at build/VHS.app; `--install --open` installs to ~/Applications and opens it.
- `tools/test.sh` runs state and actual Metal GPU fixture tests with full Xcode selected locally.
- `tools/selftest.sh` runs app actions and output-window lifecycle checks on ephemeral state.
- `tools/snap.sh` captures control default/minimum sizes in light/dark and the output. Needs GUI, Screen Recording, and System Events Accessibility access; activates the exact snapshot process.
- `tools/grid-lint.sh` and `swift tools/check-layout.swift /tmp/VHS-shots/*-layout.json` check layout.
- `tools/icon_review.sh` renders all icon appearances and small sizes.

Design rules: design/DESIGN-SYSTEM.md is the entry point; design/KIT.md and design/tokens.json define the user-approved VHS / Signal system. Read these before any UI work. Phase 4B introduced Sources/VHSSignal for existing features; every later phase must use Signal automatically as part of its normal implementation, without a separate styling request. Reuse shared semantic tokens/components across standalone, VHSGraphUI and the existing plug-in editor; never raw colors, radii, fonts or durations in views. User scene colors are content. Keep native system interactions, macOS appearance/accent overrides and per-instance ownership. The HTML sheet is a visual reference, not production UI. Do not expose future feature controls before their milestone. Apply the Signal acceptance checklist in docs/PLAN.md to each UI-bearing phase, recording deferred manual checks honestly.

VHSCore owns immutable snapshots, reducer, value history, and clock. VHSRenderer owns the shared device/queue/pipeline. AppModel owns the common frame, UI state, and output lifecycle. Live rendering never waits for GPU completion. Synchronous readback is for tests only.

The current app-only ownership above describes implemented Phases 1–3. Before production VST3, follow Phase 3A's shared-runtime decision: per-instance scene/clock/input/editor/output ownership, host-owned session recall and automation, and no shared mutable app singleton across instances. Host audio passes through unchanged. Audio callbacks never call UI/rendering, access disk, block, or wait for GPU work; use preallocated bounded handoffs. Physical audio, Core MIDI devices, and ScreenCaptureKit are standalone adapters, not plug-in capture paths. Preserve completed evidence and never count planned host checks as performed.

After changing commands, check actual Edit menu enablement before/after a slider edit, Command-Z and Shift-Command-Z, Show Output, closing/reopening output, and Command-1 from output. Do not infer menu correctness from snapshots alone. Record any manual checks not performed.
