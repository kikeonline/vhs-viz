# Standalone inputs — Phase 5B

Open **Inputs** from the standalone toolbar. Choose an audio input and mono channel or adjacent stereo pair, then **Start Audio**. VHS requests microphone access at this explicit action, after confirming a selected input/channel exists. Permission denial and restriction have separate inline states; Open Microphone Settings opens the native privacy pane. Stop Audio cancels a pending authorization result as well as an active capture. Selecting an input alone never requests access or starts capture.

Choose a hardware/virtual MIDI source, Omni or channel 1–16, then **Start MIDI**. Status reports the last supported event and held-note count. Close the popover to keep running; use Stop Audio/Stop MIDI to end capture. These inputs currently drive meters/events only; mapping to visuals and MIDI learn remain Phase 7. Phase 5B introduced no system-audio capture, presets, production host routing or external-display controls. Phase 6 subsequently adds System Audio through the native sharing picker; see SYSTEM-AUDIO.md.

## State and recovery

- Selection persists locally in UserDefaults by Core Audio device UID / Core MIDI unique ID and chosen channels. No source auto-starts after launch. Machine identities, live input values and popover visibility never enter projects, scene history or portable presets.
- Native catalogs refresh approximately once per second while input is requested, every 15 idle polls otherwise; opening Inputs schedules a refresh on the next poll. Each catalog exposes at most 256 devices/sources. UID/name conversions must fit 256-byte UTF-8 fields; oversized or ambiguous identities are excluded rather than truncated into collisions. UI offers the first 256 device channels, individually or as adjacent stereo pairs.
- A selected missing source remains selected and unavailable. It is never replaced with the system default or an identically named source. A previously explicitly started source reconnects when its stable identity returns. Audio object ID, channel count and nominal-rate changes stop/reconfigure that input; invalid selected channels require a new channel choice. MIDI endpoint/identity changes clear held notes/parser/controller state before reconnection. Hardware acceptance remains pending.
- Native audio errors trigger a fresh catalog read. Missing devices retain reconnect intent; changed device formats can restart; a failure with an unchanged available device stops capture and requires Start Audio again. No new analyzed windows for about one second clears stale displayed data; about three seconds stops the unresponsive capture with an inline retry message. Counters use the 15Hz poll cadence, so scheduling can extend these durations.
- Measured silence is distinct from unavailable/warming data. RMS/Peak display dBFS (0 amplitude is −∞), bands/onset use normalized 0...1. Clipping, invalid samples and dropped blocks have text notices. MIDI reset/loss count includes explicit disconnect/port resets. Status values do not create automatic VoiceOver announcements every frame.
- Request revisions reject stale asynchronous configuration. An authorization result arriving after Stop cannot start capture. Shutdown is terminal for a service and ignores late Start/configuration requests. Quit preserves existing save/discard/cancel behavior and awaits input teardown before approving termination.

## Ownership and callback boundary

Standalone-only dependencies: VHS → VHSDevices → VHSDeviceIO/VHSInput/VHSRealtime. VHSPluginUI has no dependency on the native device targets and gains no capture picker or microphone request. The Phase 3A VST3 callback remains unchanged.

VHSDevices.InputService owns queues, analysis, decoder and native handles on a Swift actor, off MainActor. Its poll method performs bounded drains and produces Sendable value snapshots. The standalone observation model publishes them at about 15Hz when input is requested; idle polling slows to 1Hz. Display updates remain independent of the render clock, output lifecycle and musical undo. Snapshot/self-test processes disable native polling, permissions and preference writes.

Audio uses a C AUHAL input callback: output I/O is disabled, the selected device is attached locally to the unit, desired channels map into preallocated noninterleaved Float32 buffers (max 8192 frames). The callback calls AudioUnitRender and the Phase 5A queue producer; sample timestamps are validated before integer conversion, with a local frame counter when the native stamp lacks sample time. It never invokes Swift, DSP analysis, UI, rendering, file access, a blocking lock or a retry loop. The device's system default and nominal sample rate are not changed. AU setup/start/stop/disposal occur on the worker.

MIDI uses Core MIDI's protocol-1 input port and C callback, extracting supported MIDI 1.0 channel messages and reset from UMP packets. Callback work is bounded to 256 packets/4096 words, then feeds the shared byte queue/decoder. A try-once atomic delivery gate rejects unexpected concurrent input instead of violating SPSC ownership; loss resets the decoder/held state. Unsupported UMP messages are skipped; MIDI 2.0/MPE/SysEx/clock/Active Sensing policy remains outside this phase. Native host ticks convert to a monotonic 48000-frame MIDI adapter clock with offset zero; this is timing metadata, not audio-device or DAW synchronization. Shared decoder events preserve those timestamps.

Before native start/connect, an explicit release/acquire ready flag publishes callback-context initialization. Shutdown sets stopping, disposes the native unit/port to stop new deliveries, and waits for the active-callback count to reach zero on the control thread before releasing context/queues. Callbacks never wait for teardown. The virtual-source fixtures execute these native callback and disposal paths, including under Thread Sanitizer. Actual AUHAL hardware startup/disconnect/format changes and timing performance are still unaccepted.

## Signal and acceptance

Inputs is a scrollable native popover with shared Signal semantic colors, type, spacing, buttons and SignalMeter components. Meter fill has no implicit animation; value text and accessibility labels distinguish no data from zero. Native pickers/buttons keep keyboard behavior. Output and the plug-in editor do not gain these controls. Long names have help; error/status labels can wrap. Snapshot fixtures cover Off, Listening, Silent, Waiting, Denied, Restricted, Unavailable, invalid channels and Error, with the MIDI area scrolled into view. Layout-only evidence does not establish native appearance or accessibility.

See [PHASE-5B-VERIFICATION.md](PHASE-5B-VERIFICATION.md) for automated evidence and [PHASE-4C-VERIFICATION.md](PHASE-4C-VERIFICATION.md) for attended acceptance. Core approach follows Apple's [AUHAL input/channel mapping](https://developer.apple.com/library/archive/technotes/tn2091/) and [protocol MIDI input port](https://developer.apple.com/documentation/coremidi/midiinputportcreatewithprotocol) APIs; shared analysis semantics remain in [INPUT-ENGINE.md](INPUT-ENGINE.md).
