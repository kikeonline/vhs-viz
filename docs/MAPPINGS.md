# Audio/MIDI mappings — Phase 7

Open **Mappings** in the toolbar (or Window → Show Mappings in standalone), add a mapping, choose a node/parameter target and input. Eligible targets are registry numeric parameters, including source/effect and scalar/vector graph values. Seed, colors, enums, toggles and graph ports already supplied by a connection are excluded. Up to 128 mappings are allowed per scene. Definitions use node UUID + parameter key, never chain position. Reordering preserves assignments; deleting a node or switching away from a source keeps an unresolved assignment visible. Restore the node/source or explicitly choose another target.

**Learn MIDI…** waits for the next accepted CC or nonzero note-on on the chosen channel (Omni accepts all). Review the detected channel and controller/note, then Confirm. A note learns Gate for that note; Input can subsequently select Note or Velocity. Relearn rearms discovery; Cancel, closing the popover, changing selection, editing or undoing a definition cancels the candidate without writing it. Conflicting CC or note-family assignments with overlapping channel/number scopes require Replace Conflicts or Cancel. Manual Input/Channel/Controller/Note choices remain available when there is no input. Clear Mapping removes the definition with Undo support. Manual assignments may intentionally share inputs; the conflict decision applies to learn confirmation.

In Studio One the existing `IMidiMapping` discovery bank supplies CC events through parameter changes; the plug-in never assumes raw CC bytes in `IEventList`. Start playback/live monitoring before arming Learn to avoid an initial chased CC being mistaken for a controller gesture. Inspect every candidate; Cancel/Relearn recovers a chased value. The Phase 3A route is documented in decisions/0001-vst3-runtime.md. Phase 7's native harness proves CC/note discovery and embedded state; new physical-controller and actual Studio One acceptance remain deferred. The old temporary Learn Blue control and implicit Peak/Velocity/CC1 visual offsets have been replaced by explicit persisted mappings. An empty mapping list now renders base values.

## Effective-value contract

1. Document base values are the control values. The host's base automation mailbox is authoritative for its existing RGB controls; production dynamic automation is Phase 8. Host automation changes are not a stream of local history edits.
2. Each available input is normalized to 0…1. Invert changes `x` to `1-x`; Curve applies `pow(x, curve)` with exponent 0.1…8. Minimum/Maximum are native-unit **contributions**, with `minimum + (maximum-minimum)*x`. Descending ranges are allowed. Finite contribution bounds are ±100,000.
3. Each mapping smooths its contribution with `alpha = 1-exp(-dt/tau)`, `current += alpha*(desired-current)`, using monotonic elapsed seconds. Smoothing 0 is immediate, up to 10 seconds is accepted. It starts from zero; changing a definition resets that mapping's envelope. Negative/nonfinite elapsed time does not advance smoothing.
4. Contributions for the same target add to the base, then clamp once to the registry range. There is no audio-vs-MIDI winner and no per-contribution clamping. Mapping array order is preserved by serialization; for ordinary values the sum is independent of audio/MIDI event arrival order (floating-point summation retains normal roundoff). Connected graph inputs override local mappings by making that target unavailable.
5. Audio silence is an available zero and can produce the configured range floor. No-data/disconnection/release means **zero contribution**, including inverted inputs and nonzero floors. Smoothing releases toward zero; residuals below 1e-9 are set to zero. Disabling, unresolved targets, scene replacement and removed mappings clear their envelope immediately.
6. For Any Note, the highest held MIDI note wins; equal pitches across Omni channels choose the greatest velocity. Note outputs pitch/127; Velocity outputs velocity/127; Gate outputs 1 while a matching note is held. Release falls back to the next held note, then zero contribution. Velocity-zero note-on, all-notes-off, queue loss, source/channel changes and disconnection clear notes through the shared MIDI state. CC values hold until a new CC/reset/disconnection; Omni takes the greatest received value across matching channels. A never-received/reset controller is unavailable, distinct from an explicitly received zero. CC121 resets controller availability; CC120/123–127 release notes.

The evaluator is per instance on the control/display owner. It returns an effective snapshot; it never sends a scene action, writes a document, or appends history. Preview/output use that same frame. Audio/MIDI callbacks remain bounded C handoffs. Standalone publishes analysis/MIDI snapshots through the input-service actor at its existing cadence, and never replays a pre-Stop/source-switch poll into mappings. The existing VST3 prototype supplies Peak and host MIDI; RMS/bands/transient host inputs are disabled in its editor pending the production sample handoff in Phase 8. Shared synthetic inputs already exercise all six analysis values.

## Rendering and persistence

Graph numeric values use a bounded Metal fragment uniform bank in registry/node order. A compiled graph accepts only matching node IDs/order, edges, kinds, bypass and nonnumeric values, with validated numeric values. Live modulation never requests shader compilation. Last-valid executable recovery continues to compare the original scene revision before accepting effective values; incompatible topology is rejected. Chain rendering continues to use its source/effect uniforms. No live GPU readback or GPU completion wait was introduced.

Project schema 5 requires mappings and sync fields. Versions 1–3 retain their existing migrations; version 4 migrates to an empty mapping list and Free Run. Schema 5 validates IDs, count, finite bounds, MIDI scopes, curve and smoothing before replacing the document. Mappings/sync are scene values, so edits are undoable and survive project and embedded host-state round trips. Unknown targets remain disabled/unresolved instead of retargeting. Definition UUIDs are independent of target IDs. The sync choice is persisted now; Follow DAW execution and its host UI remain Phase 8. Runtime currently uses Free Run.

Effective levels, CC/held-note arrays, candidates, smoothing state, device IDs and output windows are not serialized. No preset browser or preset storage is added here (Phase 7A).

## Stable host automation contract for Phase 8

Keep prototype source IDs 0–2 and reserved probe ID 3 fixed. Keep the hidden controller discovery bank at `0x1000 + zeroBasedChannel*128 + CC` (0x1000…0x17ff). Reserve **256 dynamic numeric slots** at 0x2000…0x20ff. Each slot stores an optional node UUID/parameter key in the versioned host envelope, with normalized host values converted through that target's registry range into base values **before** mapping contributions.

Allocation is explicit: an unbound target takes the lowest never-bound slot; exposing a target already bound returns the existing slot. Reorder/rewire/scene edits never renumber or compact slots. Missing/deleted targets retain their slots as visibly unresolved; a slot may only be rebound by an explicit user operation, never by loading/reordering a graph. At capacity, reject a new exposure with a clear message; do not steal lanes. Bindings serialize with song state; state restore before editor creation restores the table first. Host gestures and host undo own automation changes. These IDs/table rules are the Phase 7 specification; production slot exposure, host envelope implementation, tempo/transport and automation certification belong to Phase 8.
