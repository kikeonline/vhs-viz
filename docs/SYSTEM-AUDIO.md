# Standalone System Audio — Phase 6

In Inputs, choose **System Audio**, then **Choose Audio to Share…**. macOS supplies its sharing picker for one application or display. VHS creates a ScreenCaptureKit stream only after selection. Cancellation leaves System Audio selected with capture off; retry is explicit. Denial also offers Open Screen & Audio Settings for the native privacy pane. No share, filter, window/display identity or live value is saved in a project/preset. Only the local source-kind preference is remembered, and launch never starts sharing.

The same RMS/Peak/band/transient meters analyze the selected audio. Requested format is stereo Float32 at 48 kHz, with microphone capture disabled and current-process audio excluded. Physical channel controls are replaced with a read-only format label. System audio never requests microphone access. App/display audio scope, real permissions, macOS sharing indicators and playback behavior remain attended acceptance; synthetic samples cannot prove that an actual selected application is audible.

## Control and recovery

InputService owns either physical capture or a system session, with one shared worker-side analyzer. Configurations share a monotonically increasing audio revision, including source switches. The UI accepts terminal/status acknowledgements only for its current revision, so an older poll or delayed microphone authorization cannot cancel/start a newer source. Selecting System Audio stops the physical unit first. Switching to physical capture requests system stop and gates physical startup until native stop completes. It does not substitute another source when sharing is cancelled, denied, stopped or revoked.

The native state machine distinguishes Off, Picking, Starting, Capturing, Cancelled, Denied, Failed, Ended and Stopping. Each picker observer has an immutable request generation; stale callbacks are ignored. A cancelled request queued before presentation never instantiates a picker. Stop during asynchronous start waits for that completion, then stops/releases that stream. Later explicit requests supersede the continuation but do not reuse a previous receiver. User/system sharing termination remains terminal until a new explicit request. Format/buffer failures stop the session and preserve an inline failure message.

No new analyzed windows for roughly one second at normal 15Hz polling clears the displayed data to a dash/Waiting for system audio; it does not fabricate measured silence or stop an otherwise valid silent share. Actual zero-valued delivered samples produce the distinct Silent state. Subsequent timestamp gaps reset shared-engine warm-up. Scheduling can extend this freshness interval.

Shutdown requests native stop asynchronously while leaving the main and sample queues free. It waits up to 500 ten-millisecond polling intervals before releasing the control handle; native stop completions/receivers retain their own queue owner if the framework is slow. This prevents use-after-free and unbounded UI blocking; it is not a measured OS shutdown-time guarantee. Active capture quit/source handoff remain manual acceptance.

## Native sample boundary

VHSSystemIO is a standalone-only Objective-C/C target. Picker/stream configuration and teardown run on the main dispatch queue. The serial sample handler implements SCStreamOutput in Objective-C and never enters Swift/UI/rendering. Only audio output is registered: no screen, camera, microphone, recording or clip-buffer output. The otherwise unused stream video configuration is minimal (16×16, one frame/second, depth 3). Defensive non-audio callbacks return before inspecting their sample buffers. No image is read back, retained for app use, or written; no audio/video recording output exists.

The PCM receiver validates ready/valid buffers, linear PCM native packed Float32, mono/stereo, integral rates 8–192 kHz, 1–8192 frames, numeric epoch-zero timestamps and buffer byte sizes. Presentation time converts to an absolute frame index at the supplied rate. It supports interleaved and noninterleaved buffers. A preallocated two-buffer AudioBufferList is passed with the exact one/two-buffer byte length required by the format; using the larger backing-storage size for a one-buffer layout was rejected by this OS and is covered by fixtures.

Core Media's retained-block accessor uses null allocators, refusing buffers that require a new contiguous data allocation/copy. Its bounded reference is released after samples have been copied into the Phase 5A queue. Unsupported/malformed data produces a gap/error rather than an unsafe reinterpretation. Queue overflow carries the shared drop/generation policy. This is a ScreenCaptureKit sample-queue path, not a host audio callback; no hard real-time or measured audio-to-display latency claim is made.

Each stream has its own enabled receiver and a strong queue owner. On stop the receiver is disabled permanently; the control thread barriers the serial sample queue before advancing the discontinuity generation. Late callbacks from old streams cannot regain an enabled receiver. Stop completion removes the old output before a new selection is presented. The worker reads that session's queue only while it owns the active system intent; physical input has separate storage. Queue ownership survives control-handle release and queued callbacks. There are no shared mutable plug-in singletons.

The app never enumerates screen content itself or starts a stream automatically to check access. Only the explicit native picker supplies a filter. Native observer/stream failure callbacks supply denial/termination status. NSScreenCaptureUsageDescription and NSAudioCaptureUsageDescription explain the use; the existing microphone description remains for physical input. No new file/project schema, mapping, undo, command-menu or output behavior is introduced.
